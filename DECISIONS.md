# Decisions & assumptions

Everything below was decided autonomously while building this project without
hardware and without access to the live APIs. Each item says what was chosen
and why, so it is easy to revisit.

## Environment / what could and could not run

- **PlatformIO 6.x installed via pip** and the **pioarduino platform 53.03.13**
  downloaded successfully from GitHub (`platform-espressif32.zip`), including
  toolchain and Arduino core 3.1.x. One mirror (`usc1.contabostorage.com`) for
  `tool-mklittlefs` was blocked, PlatformIO fell back to another mirror – no impact.
- **Live API calls were blocked** by the sandbox egress policy (HTTP 403 on CONNECT):
  - `https://www.mvg.de/api/bgw-pt/v3/locations?query=Marienplatz&locationTypes=STATION` → 403
  - `https://api.open-meteo.com/v1/forecast?...` → 403
  - `https://efa.mvv-muenchen.de/` → 403
  Consequently all fixtures in `test/fixtures/*.json` are **synthetic** (see
  `test/fixtures/README.md`), generated by `tools/make_synthetic_fixtures.py`.
  `tools/fetch_fixtures.sh` captures real ones into `test/fixtures/real/`, which
  `test_real_fixtures` checks automatically when present.
- Because the MVG API could not be tested, there was no evidence it is unusable,
  so the MVG provider is the default; the EFA fallback was **not** implemented,
  but the provider sits behind `core::TransportProvider` so it can be added.
