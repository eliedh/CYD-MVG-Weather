# Decisions & assumptions

Everything below was decided autonomously while building this project without
hardware and without access to the live APIs. Each item says what was chosen
and why, so it is easy to revisit.

## 1. Environment – what ran and what was blocked

| Step | Result |
|---|---|
| `pip install platformio` | ✅ PlatformIO Core 6.2.0 |
| pioarduino platform 53.03.13 (`platform-espressif32.zip` from GitHub) | ✅ downloaded and installed, toolchain + Arduino core 3.1.x fetched on first build |
| `tool-mklittlefs` mirror `usc1.contabostorage.com` | ❌ 403 (egress policy) – PlatformIO fell back to another mirror, no impact |
| Library downloads (LovyanGFX 1.2.32, ArduinoJson 7.4.3, AsyncTCP 3.5.0, ESPAsyncWebServer 3.12.1, Unity) | ✅ |
| Inter font download from GitHub releases | ✅ (TTFs committed under `tools/fonts/`, OFL) |
| `https://www.mvg.de/api/bgw-pt/v3/locations?query=Marienplatz&locationTypes=STATION` | ❌ `CONNECT tunnel failed, response 403` (sandbox egress policy) |
| `https://api.open-meteo.com/v1/forecast?...` | ❌ same 403 |
| `https://efa.mvv-muenchen.de/` | ❌ same 403 |
| `pio run` for all 5 envs, `pio test -e native` | ✅ (see summary in the PR) |
| Host preview rendering + Playwright screenshots of web pages | ✅ |

Consequences:
- **All fixtures are synthetic** (`test/fixtures/README.md`), generated by
  `tools/make_synthetic_fixtures.py` from the publicly known response shapes.
  `tools/fetch_fixtures.sh` captures real responses into `test/fixtures/real/`,
  which `test_real_fixtures` parses automatically when present.
- Because the MVG API could not be tested, there was no evidence that it is
  unusable, so **MVG is the provider**; the EFA fallback was **not**
  implemented. Providers sit behind `core::TransportProvider` /
  `core::WeatherProvider` so an EFA implementation can be dropped in.
- Nothing ran on real hardware. Everything hardware-related is written to the
  owner's verified notes but untested.

## 2. Product

- **Name: "Abfahrt"** (German for "departure"; short, readable on the
  hotspot name). Hotspot `Abfahrt-Setup-XXXX` (XXXX = last two MAC bytes),
  mDNS `abfahrt.local`. Change in `board_config.h` (`PRODUCT_NAME`,
  `PRODUCT_HOSTNAME`).
- **Default language German**, chosen on the first setup page; the hotspot
  screen itself is bilingual because the language is not known yet.
- **Setup hotspot is open (no password).** Joining via QR must be effortless
  for a non-technical user; the hotspot only exists during setup. Trade-off:
  someone nearby could configure the device during those minutes.
- **Settings page has no login.** It is only reachable on the home network.
  Wi-Fi credentials are never returned by the API.
- Up to **4 stops**, up to **20 departures per stop** fetched (also used for the
  line/direction checkbox list – at very busy stops a rarely served direction
  may not appear in the list until it shows up in the next 20 departures).

## 3. Departure logic

- **Merged list** of all stops, sorted by real-time departure (scheduled if no
  real-time). Ties: stop order, then line label. Exact duplicates removed.
- **Reachability**: departures that leave before you could walk to the stop
  (`seconds until departure < walking time`) are **shown greyed out**
  (muted badge, text, minutes and real-time dot) instead of hidden. To keep
  catchable departures on screen, at most **2** such rows are kept overall
  (`kMaxUnreachableRows`) – the ones closest to still being catchable.
  Departures that already left are hidden (no grace period).
- **Next catchable** = first reachable, non-cancelled row; highlighted with a lighter row
  background. "leave in N min" / "in N Min. losgehen" is shown only if that
  stop has a walking time > 0 (otherwise it would just repeat the countdown);
  0 → "leave now".
- **Minutes** = floor(seconds/60); `0` shows "now"/"jetzt"; ≥ 60 min shows the
  clock time (HH:MM).
- **Real-time** marked with a small green dot and white minutes; scheduled-only
  departures have grey minutes and no dot. **Delay** `+N` in amber next to the
  minutes (only for real-time, only if > 0). **Cancelled**: dimmed badge,
  struck-through destination, "fällt aus"/"cancelled" in red instead of minutes;
  cancelled rows are still shown (useful information) but never highlighted.
- **Filters** are *exclusions*: `"U3"` hides the line, `"U3>Fürstenried West"`
  one direction. New destinations (e.g. short-turn trips) therefore show up by
  default instead of silently disappearing.
- **Stop label** on the board only when > 1 stop. Default label: name without
  "München, ", and the part before ", " when the name is long
  ("Gauting, Bahnhof" → "Gauting"). Editable on the settings page.
- **Service messages**: shown when they name a line that currently departs from
  a configured stop (after filters) and are valid now. Matching uses label +
  transport type (so tram 23 ≠ bus 23). Max 6, de-duplicated by title, text
  HTML-stripped and truncated to ~900 bytes. Banner shows the first; a tap
  pages through all of them (tap = next page / next message / back).
- **Stale marker**: shown when the departure data is ≥ 1 min old *and* the
  last round failed, or ≥ 3 min old in any case. Old data stays on screen.

## 4. Weather

- Open-Meteo with `timeformat=unixtime` (no date parsing on the device) and
  `forecast_days=2` (no reliance on `forecast_hours`).
- **"Rain chance" in the header = max precipitation probability over the next
  6 hours** (more useful at a glance than the whole-day maximum, which is shown
  on the detail screen instead).
- Hourly detail: 8 columns starting with the current hour ("Jetzt"/"Now").
- WMO codes mapped to 10 icon types and 28 DE/EN descriptions.
- Location: first stop with coordinates, or the override (picked via the stop
  search or entered as lat/lon).

## 5. Display & UI

- **Rendering**: one 320×40 RGB565 sprite, bands pushed only when their
  FNV-1a hash changed (instead of hand-maintained dirty flags – simpler and
  impossible to forget a case). `waitDMA()` before every reuse; no double
  buffering.
- **Fonts**: Inter Medium 13 px (small), SemiBold 17 px (body), SemiBold 23 px
  (titles/minutes), Bold 14 px ASCII (badges), Medium 44 px digits only (big
  temperature/countdown). Latin-1 + `– — ‘ ’ ‚ “ ” „ • … € ← ↑ → ↓ −`.
  Soft hyphen (U+00AD) is missing in Inter and is stripped from texts.
- **Colours** in `lib/ui/src/theme.h`: near-black blue background, white /
  grey text hierarchy, green accent (real-time, "leave in", buttons), amber for
  delays/notices/stale, red for cancellations.
- **Line badge colours/shapes** (`line_style.cpp`) approximate MVG/MVV: U-Bahn
  squared rectangle per line (U7/U8 split two-colour), S-Bahn pill per line
  (S8 black with yellow text), tram red rectangle, city bus dark teal rounded,
  ExpressBus `X…` green, night lines `N…` dark, MVV regional bus blue,
  trains grey. These are approximations from memory, not official values.
- **Touch**: tap = press < 900 ms with < 40 px movement; long-press = 1 s
  (fires while still pressed). No swipes anywhere.
- **Header tap** → hourly forecast; **banner tap** → notice; **long-press
  anywhere** (when online) → settings QR. Detail screens auto-return after
  30 s, settings QR after 90 s.
- **Touch calibration**: LovyanGFX `calibrateTouch()` (4 corners), stored as
  8 values in the settings JSON. Reachable from the settings page and by
  releasing BOOT between 3 and 10 s. Until calibrated, the raw range
  300–3900 / 200–3700 with `offset_rotation 0` is used – this default is a
  guess and may be mirrored on the owner's board; calibration fixes it.
  Note: `calibrateTouch()` waits for touches without timeout; if touch were
  completely broken, a power cycle exits it.
- **QR codes**: LovyanGFX's built-in encoder (no extra library), ECC level M,
  drawn on a white rounded card with a quiet zone. The "almost done"/settings QR
  encodes `http://<IP>/` (more reliable than `.local` on Android); the URL and
  IP are printed next to it.

## 6. Night mode & brightness

- Night window default **22:00–06:30, mode "dim"** (backlight level 4/255).
  "dark" turns the backlight off. Setup screens are never dimmed.
- First tap at night only wakes the screen (30 s, extended while used).
- Auto brightness: LDR averaged (8 samples, EMA), linear map between
  `LDR_BRIGHT_RAW = 40` (≤ → 100 % of the user brightness) and
  `LDR_DARK_RAW = 600` (≥ → `LDR_MIN_PERCENT = 25 %`). **These thresholds are
  guesses** – the log prints `LDR raw=…` every 30 s for calibration. ADC
  attenuation 0 dB (most sensitive), after the required dummy `analogRead(34)`.
- Backlight changes fade in steps of 8/255 every 20 ms (no flashing).

## 7. Networking

- **Wi-Fi state machine**: no credentials → hotspot; credentials → connect,
  after 30 s "No Wi-Fi" screen while retrying every 20 s; long-press there →
  hotspot again (STA retries paused to keep the hotspot stable; device
  restarts after 10 min if the re-opened hotspot is not used). Short drops
  while online only show "Wi-Fi lost" in the header.
- After successful setup the hotspot stays up **90 s** so the phone can show
  "Connected!". Requests are routed by the interface they arrive on, so a
  phone already back on the home Wi-Fi gets the settings page.
- If the phone drops off the hotspot while the ESP32 switches channel to join
  the router (normal in AP+STA mode), the setup page shows "Look at the
  board" instead of a false error.
- Credentials stored by the firmware (NVS), `WiFi.persistent(false)`.
- **TLS without certificate validation** (`setInsecure()`), as specified – the
  data is public; pinning would break on certificate rotation.
- Fetch intervals: departures 45 s (20 s after an error), messages 5 min,
  weather 15 min (2 min after an error); first weather 8 s and first messages
  16 s after the first departures (staggered).
- Departure requests omit `transportTypes` unless a stop is restricted, and
  never send `SCHIFF` (unknown whether every API version accepts it);
  filtering is done locally anyway.
- `User-Agent: Mozilla/5.0 (compatible; Abfahrt-CYD/1.0)`.
- Captive-portal detection URLs for Android, Apple, Windows and Firefox
  redirect to `http://192.168.4.1/`; DNS answers every name with the AP IP.
- Web requests that need the internet (stop search, line lists) are **jobs**
  executed by the net task and polled by the page – the async web server task
  never blocks on HTTPS.
- Libraries: `ESP32Async/ESPAsyncWebServer` + `ESP32Async/AsyncTCP` (the
  maintained fork that supports Arduino core 3.x); DNSServer/mDNS from the core.

## 8. Settings & storage

- One JSON document in NVS (`abfahrt/cfg`); tolerant parsing with clamping
  (walk 0–60 min, brightness 5–100 %, times 0–1439, ≤ 4 stops, ≤ 64 excludes per
  stop, invalid/zero coordinates rejected).
- The settings page posts the whole document; unknown keys are ignored and the
  touch calibration cannot be overwritten through the API.
- Saving is debounced (1.5 s) and done by the UI loop.
- **Factory reset ("erase everything")** – from the settings page, BOOT 10 s,
  or on the device (long-press → *Reset…* → press-and-hold *Erase*; two
  deliberate steps so it cannot happen by accident). It clears our namespace,
  the Wi-Fi driver's credentials, stops the Wi-Fi driver and erases the whole
  NVS partition, then restarts into the setup hotspot like a new unit. The net
  task is parked first so it does not touch Wi-Fi/NVS during the erase.
- **Wi-Fi setup page only over the hotspot**: on the home network `/setup`
  redirects to the settings page and `/api/wifi` is refused (403). Changing
  networks from the home network cannot be confirmed safely (the phone loses
  the device mid-switch) and previously would not have saved the new
  credentials. *Change Wi-Fi* restarts into the hotspot instead.

## 9. Build & CI

- `default_envs = cyd_st7789`, so `pio run` / `pio run -t upload` target the
  owner's board. All envs build with `pio run -e <env>`; CI builds every env.
- `native` env has a stub `main` so `pio run -e native` also succeeds; tests run
  with `pio test -e native`.
- Merged image produced by a post-build script with `esptool merge_bin`
  (bootloader 0x1000, partitions 0x8000, boot_app0 0xe000, app 0x10000;
  `dio`, 40 MHz, 4 MB) → flash at 0x0.
- `-std=gnu++17` everywhere.
- Web pages: hand-written HTML/CSS/JS, no framework, no external resources
  (the hotspot has no internet), minified + gzipped into `web_assets.h` at build
  time; the build fails if a page's DE and EN dictionaries differ.
- Generated files (fonts, web assets, screenshots) are committed so a plain
  `pio run` needs no extra Python packages.
- No license file was added – that is the owner's choice.

## 9b. BOOT button safety (found on the first hardware test)

- On the first real board the device showed the reset countdown right after
  boot and reset itself in a loop: GPIO0 read LOW continuously. GPIO0 is also
  wired to the CH340 auto-reset circuit, so a serial monitor holding DTR/RTS
  can pull it low. Fixes:
  - the button is ignored until it has been seen **released** for 300 ms after
    boot (a pin that is low from power-on never triggers anything);
  - actions happen on **release** only (3–10 s → calibration, 10–30 s →
    factory reset); at 10 s the screen says "release now: erase everything";
  - held > 30 s → treated as stuck, ignored until released;
  - `monitor_rts = 0`, `monitor_dtr = 0` in `platformio.ini`.

## 9c. Memory (found on the first hardware test)

- The first HTTPS request (stop search) crashed the device: ~84 kB free heap
  before the TLS handshake (which needs ~45–55 kB); other tasks' `new` then
  failed and aborted (`operator new` → `std::terminate`) – once in the async
  web server parsing the page's polling request, once in the UI's per-second
  `buildBoard()` vector. Fixes:
  - `buildBoard()` uses a static work buffer and `std::sort` (no heap);
  - the view model points at the snapshot's messages instead of copying them;
  - service messages: max 4, text 640 bytes (was 6 × 900);
  - removed a duplicate 7 kB departure buffer in the net task;
  - net task stack back to 16 kB, AsyncTCP task stack 16 → 10 kB
    (`CONFIG_ASYNC_TCP_STACK_SIZE`);
  - the settings page polls jobs less often;
  - every HTTPS request is skipped (logged as "low memory") when free heap is
    below 70 kB or the largest block below 32 kB, instead of risking a crash.
  The log prints heap/largest block before and heap/min/stack after every
  request, so the remaining headroom is visible.

## 10. Known gaps / not done

- No EFA fallback provider (MVG could not be evaluated).
- No OTA (out of scope; `huge_app.csv`).
- Hardware behaviour (touch orientation, LDR range, backlight PWM, real heap
  headroom under TLS + web server) is unverified.
- Line colours are approximations.
